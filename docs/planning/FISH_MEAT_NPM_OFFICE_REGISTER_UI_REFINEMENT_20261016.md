## Why these are separate records
A Fish/Meat fee registration identifies the vendor for that revenue source. It is not the same as an approved New Public Market (NPM) stall tenancy. Josephine Reyes may already be registered for Fish fees while her separately requested Fish Area Stall 2 NPM tenancy is pending Head review. The new NPM picker now explicitly distinguishes the two registrations, rather than showing an ambiguous “Registered” status.

## Financial and safety constraints
- Existing registered vendor ID, vendor display identity, type, tax year, registration kind, status, audit and revenue records are unchanged by office-detail correction.
- The Head-only existing-registration correction API validates tenant and role, and refuses stale before snapshots with a conflict. The UI displays a refresh/retry message.
- No NPM tenancy is created by Fish/Meat identity selection; it still requires Head verification and explicit approval in the established NPM workflow.
- Collected Vendor Fee and Weight & Measure totals are the already-recorded backend values. No cash, SRC, OR, CT, remittance, collection, rate, or payment record is generated by the editor.
- Address double-paste cleanup is **presentation only**; the database remains unchanged until the Head explicitly edits and saves the address.
